BlackLang Documentation

BlackLang

BlackLang, AI ajanlarının uygulama niyetini kısa, net ve doğrulanabilir bir kaynak dille yazması için tasarlanan deterministik bir dildir.

Current version: 0.1.0-dev Target: Web applications Source: .black Theme: .blackthm
Minimal fikir
Human request
  to AI coding agent
  to .black source
  to black compiler
  to generated web application

İlk hedef Python veya JavaScript'i tamamen değiştirmek değildir. İlk hedef, web uygulamalarında tekrar eden model, form, tablo, validation, API ve güvenlik niyetlerini daha küçük bir kaynak temsille anlatmaktır.

Quick Start

En küçük çalışan akış bir `.black` dosyası yazmak, validate etmek ve web çıktısı üretmektir. AI ajanı da insan geliştirici de aynı dosyayı okuyup aynı sonucu alır.

examples/warehouse/app.black
app Warehouse

entity Product {
  sku text required unique
  name text required
  stock number default 0
  price money
  computed inventoryValue money = stock * price label "Inventory Value"
}

page Products {
  source Product

  table {
    columns sku, name, stock, price, inventoryValue
    search sku, name
  }

  form {
    fields sku, name, stock, price
  }

  actions create, edit, delete
}

Bu blok Product verisini, Products ekranını, tablo kolonlarını, form alanlarını ve CRUD davranışlarını tek kaynakta toplar. Generator bu niyetten TypeScript, React, API, validation ve database tarafını üretir.

Kurulum

BlackLang'in hedef dağıtımı tek binary modelidir. Olgun sürümde kullanıcı sadece `black` komutunu indirip çalıştırabilmelidir; compiler için ayrıca Python veya Node.js zorunlu olmamalıdır.

Planlanan kullanım
black init
black format --check --json
black lint --json
black validate --json
black build

npm yolu da yaygınlaşma için planlanır. npm paketi platforma uygun binary'yi çağırır; BlackLang'in compiler mantığı yine tek binary içinde kalır.

Proje Yapısı

BlackLang projelerinde kaynak gerçekliği `.black` dosyalarıdır. Generated dosyalar compiler çıktısıdır ve normalde elle düzenlenmez.

Temel klasör mantığı
blacklang/
  BLACKLANG.md
  SPEC.md
  AGENTS.md
  blacklang.toml
  examples/
    warehouse/
      app.black
  generated/
  packages/
    cli/

AI ajanı projeye girdiğinde önce yerel öğrenme dosyalarını ve `blacklang.toml` sürüm bilgisini okur. Sonra sadece gereken `.black` kaynaklarını değiştirir.

Syntax Temeli

Dil kısa olmalı ama şifreli olmamalıdır. `app`, `target`, `entity`, `page`, `table`, `form`, `actions`, `when` gibi tanıdık kelimeler AI'nin ilk okuma maliyetini düşürür.

Top-level bloklar
app Warehouse

target web {
  frontend react
  backend node
  database sqlite
}

entity Product {
  name text required
}

page Products {
  source Product
}

Her davranış için tek syntax hedeflenir. Bu, hem compiler hatalarını daha stabil yapar hem de AI ajanının "hangi kullanım doğru" diye tahmin yürütmesini azaltır.

app

`app`, uygulamanın adını belirler. Bir BlackLang projesinde tam olarak bir ana uygulama adı olmalıdır.

Syntax
app Warehouse

Generator bu adı package metadata, arayüz başlığı ve çıktı dokümantasyonu gibi yerlerde kullanabilir. İsim PascalCase yazıldığında hem insan hem AI için daha okunaklı kalır.

target

`target`, `.black` kaynağının hangi platform ve generated stack için yazıldığını açıkça belirtir. v0.1'de bilinçli olarak tek çalışan hedef desteklenir: web, React, Node ve SQLite.

Web target
target web {
  frontend react
  backend node
  database sqlite
}

Bu blok, ileride plugin/adapter sisteminin bağlanacağı yerdir. PostgreSQL, mobile, desktop, API-only veya farklı backend hedefleri generator gerçekten o çıktıları üretebildiğinde açılmalıdır. Blok yoksa mevcut generator eski varsayılan stack'i kullanır: `web`, `react`, `node`, `sqlite`.

entity

`entity`, saklanacak uygulama verisini anlatır. Normal web stack'te model, validation, database schema ve API type parçalarına bölünen niyet burada tek blokta ifade edilir.

Ürün modeli
entity Product {
  sku text required unique length 3..40
  name text required label "Product Name"
  stock number default 0 min 0
  price money min 0
  computed inventoryValue money = stock * price label "Inventory Value"
}

Field adı solda, tipi yanında, kuralları ise aynı satırda yer alır. Bu sıra, AI'nin satırı tek seferde okuyup veri niyetini anlamasını kolaylaştırır.

computed

`computed`, saklanan field'lardan okuma amaçlı hesaplanan değer üretir. İlk sürümde database kolonu değildir, form input'u değildir; generated table ve detail UI içinde hesaplanır.

Computed display field
entity Product {
  stock number default 0
  price money default 0
  computed inventoryValue money = stock * price label "Inventory Value"
}

page Products {
  source Product

  table {
    columns stock, price, inventoryValue
  }
}

v0.2 syntax'ı `computed name type = left operator right` şeklindedir. Desteklenen tipler `number`, `integer`, `decimal`, `money`; desteklenen operatörler `+`, `-`, `*`, `/`. Operand'lar aynı entity içindeki number-like field'lar veya numeric literal değerler olmalıdır.

Generated React mantığı
function computeInventoryValue(item: Product) {
  const value = Number(item.stock ?? 0) * Number(item.price ?? 0);
  return Number.isFinite(value) ? value : null;
}

Bir computed field, kaynak aldığı field'lardan biri role/field-level permission ile gizlenmişse generated UI'da kendisi de gizlenir. Search, filter ve sort desteği sonraki data logic aşamasına bırakılmıştır.

query

`query`, düşük stok gibi özel listeleri saklanan entity field'ları üzerinden tanımlar. Filtre, sıralama ve kayıt sınırı server tarafında uygulanır; aynı sorgu birden fazla generated sayfaya bağlanabilir.

Warehouse: düşük stok listesi
query LowStockProducts {
  source Product
  where stock < 10
  sort stock asc
  limit 50
}

page LowStock {
  source Product
  query LowStockProducts

  table {
    columns sku, name, stock, price, inventoryValue
    search sku, name
    paginate 10
  }
}

Bu örnek, yukarıdaki Product modelinden stok adedi 10'dan küçük olan en fazla 50 ürünü seçer. Stok artan sıradadır; eşit stok değerlerinde `id asc` kullanılır. Form ve actions olmadığı için LowStock sayfası salt okunurdur. Computed `inventoryValue` tabloda gösterilebilir; query koşulunda veya sort alanında kullanılamaz.

Query top-level tanımlanır ve tek `source Entity` kullanır. Sayfa kendi `source` satırını korur, `query Name` ile sorguya bağlanır; iki source aynı olmalıdır. Birden fazla `where` satırı AND ile birleşir. Tek bir opsiyonel `sort field asc|desc` kullanılabilir. Sort yoksa varsayılan `id asc`; limit yoksa varsayılan 100'dür. `limit`, 1 ile 1000 arasında tam sayı olmalıdır.

Field tipine göre literal örnekleri
where status == "draft"
where stock < 10
where price >= 12.50
where active == true
where dueDate < "2026-09-06"
where scheduledAt >= "2026-09-06T12:00:00Z"

Her koşul query source entity'sinde bulunan, örnekteki tipe uygun bir field gerektirir. Text/email/date/datetime değerleri tırnaklı, numeric ve boolean değerler tırnaksızdır. `number` ve `integer` 32-bit tam sayı; `decimal` ve `money` sonlu ondalık literal kabul eder. `==` ve `!=` tüm desteklenen stored primitive tiplerde; `<`, `<=`, `>`, `>=` numeric/date/datetime tiplerinde geçerlidir. Relation, computed ve generated system field'ları, parametreler, OR, join, aggregate ve raw SQL bu MVP'nin dışındadır.

Generated LowStock sayfası `GET /api/lowstock/query` üzerinden yüklenir. Mevcut entity listesi ve CRUD route'ları kendi davranışını sürdürür; relation seçenekleri normal entity listesinden gelir. Sayfaya bağlanmamış query bağımsız endpoint oluşturmaz. Table search/filter/pagination ve opsiyonel table sort, server'ın döndürdüğü sınırlı liste üzerinde çalışır. Bağlı sayfadaki başarılı mutation sonrası query yeniden yüklenir.

Auth, page access, entity read ve response field hiding kuralları korunur. Koşul veya sort alanı mevcut role için okunabilir değilse query endpoint'i 403 döndürür. Query filtreleri ownership/tenant/row authorization kuralı oluşturmaz; mevcut detail ve mutation endpoint'lerini daraltmaz.

AI için kısa öğrenme ve etki analizi
black docs query --json
black explain query --json
black inspect --affected LowStockProducts --json
black inspect --affected Product.stock --json
black validate --json
black build --json

Tam kurallar query referansında, stabil hata kodları diagnostics referansında bulunur. Query tanımı ve page bağlantısı JSON, BlackIR, inspect/affected ve generated OpenAPI çıktısında görünür.

Field Tipleri

Field tipi verinin nasıl saklanacağını ve hangi validation davranışlarının üretileceğini belirler.

Desteklenen temel tipler
name text required
stock number default 0
quantity integer min 1
price money min 0
email email unique
active boolean default true
createdAt datetime

v0.1 alan tipleri: `text`, `number`, `integer`, `decimal`, `money`, `email`, `boolean`, `date`, `datetime`. Entity adı da relation tipi olarak kullanılabilir.

Modifier örnekleri
sku text required unique length 3..40 regex "^[A-Z0-9]+$"
website text optional url
discount money min 0
name text required placeholder "Enter product name" help "Visible in lists"

page

`page`, generated web uygulamasındaki ekran niyetini anlatır. Sayfa hangi entity'den beslenecek, hangi tablo ve form alanlarını gösterecek, hangi aksiyonları açacak burada belirlenir.

Sayfa tanımı
page Products {
  source Product

  table {
    columns sku, name, stock, price
    search sku, name
  }

  form {
    fields sku, name, stock, price
  }

  actions create, edit, delete
}

`source`, var olan bir entity'yi göstermelidir. Table ve form alanları source entity içinde yoksa validator stabil hata kodu üretir. İsteğe bağlı `query Name` satırı, listeyi aynı source entity'yi kullanan özel sorguya bağlar.

view

`view`, bir page içindeki generated section sırasını `.black` kaynakta kontrol eder. Böylece formu tablonun üstüne almak için React veya CSS çıktısını elle düzenlemek gerekmez.

Sayfa içi section sırası
page Products {
  source Product

  view {
    order form, table, detail
  }

  table {
    columns sku, name, stock, price
  }

  form {
    fields sku, name, stock, price
  }
}

v0.2 başlangıcında desteklenen section adları `table`, `detail` ve `form`dur. Yazılan section'lar önce gelir; eksik bırakılan destekli section'lar varsayılan `table, detail, form` sırasıyla sona eklenir. Generator bu niyetten `.bl-view-section-*` class'ları ve deterministik order CSS'i üretir.

table

`table`, listeleme yüzeyini tarif eder. Kolonlar, arama alanları, filtreler, sıralama ve pagination aynı blokta tutulur.

Tablo davranışı
table {
  columns sku, name, stock, price
  search sku, name
  filter stock
  sort stock desc
  paginate 10
}

Generator table tanımından React liste görünümü, search state, filtre kontrolleri, pagination ve field bazlı görünürlük kontrollerini üretebilir. Query'ye bağlı sayfalarda bu araçlar query'nin döndürdüğü sınırlı liste üzerinde çalışır; table sort belirtilmezse query sırası korunur.

form

`form`, create ve edit işlemlerinde kullanılacak alanları belirler. Field metadata varsa label, placeholder, help ve inline validation mesajları buradan üretilir.

Form alanları
form {
  fields sku, name, stock, price
}

Relation field kullanıldığında generator select input üretir. Zorunlu relation için ilişkili kayıt yoksa submit kapatılıp kullanıcıya önce hangi kaydı oluşturması gerektiği gösterilir.

actions

`actions`, sayfada hangi veri işlemlerinin aktif olacağını söyler. Aynı liste, API route üretimini ve arayüz kontrol görünürlüğünü etkiler.

Desteklenen action değerleri
actions create, edit, delete, archive, restore

`archive`, soft delete mantığıyla `archivedAt` set eder. `restore`, kaydı tekrar görünür yapar. Role sistemi varsa action butonları izinlere göre gizlenir.

layout

`layout`, sayfaların generated uygulama kabuğunda hangi sırayla görüneceğini kontrol eder. Şimdilik sidebar odaklıdır.

Sidebar düzeni
layout AdminLayout {
  sidebar {
    item Products
    item Customers
    item Orders
  }
}

page Products {
  layout AdminLayout
  source Product
}

Explicit layout yoksa navigation sayfa tanım sırasından türetilebilir. Küçük ekranlarda generated app drawer menüye geçer.

auth

`auth`, giriş ve oturum niyetini kaynak dil seviyesinde tanımlar. v0.1 email ve password stratejisiyle cookie session üretimini destekler.

Cookie session auth
auth {
  strategy emailPassword
  session cookie

  user {
    name text required
    email email required unique
  }
}

Bu blok register, login, logout, `/api/auth/me`, password hashing ve cookie session davranışlarının üretilmesine temel olur.

role ve access

`role`, kullanıcı izinlerini tanımlar. `access`, sayfanın hangi role veya auth kapsamına açık olduğunu söyler.

Rol ve sayfa erişimi
role Admin {
  allow all
}

role Worker {
  allow read Product
  deny read Product price
  allow update Product stock
}

page Products {
  source Product
  access Admin, Worker
}

Generated API, sayfa ve action seviyesinde izinleri uygular. Field-level `deny` ile hassas alanlar API response ve React görünümünden gizlenebilir.

workflow

`workflow`, bir entity'nin iş süreci durumlarını ve geçişlerini tanımlar. Özellikle sipariş, destek talebi, onay akışı gibi sistemlerde kullanılır.

Durum geçişleri
workflow OrderPreparation {
  source Order
  states draft, picking, verified, packaged, shipped

  transition ship {
    from packaged
    to shipped
    allow Admin
  }
}

Workflow source entity içinde `status text` olmalıdır. Generator transition route, permission check, status update, UI button ve audit log kaydı üretebilir.

state

`state`, generated React ekranında kullanılacak client-side UI durumunu ifade eder. Modal, seçili kayıtlar ve aktif filtre gibi davranışlar burada tanımlanabilir.

Sayfa state'i
state OrdersPageState {
  selectedOrders Order[]
  activeFilter text
  modal createOrder closed
}

`OrdersPageState` veya `OrdersState`, `page Orders` ile eşleşebilir. Modal tanımı open/close helper üretimine temel olur.

component

`component`, tekrarlı UI niyetlerini kaynak seviyesinde tanımlar. İlk kullanımda field değerine göre variant seçimi desteklenir.

StockBadge
component StockBadge {
  input stock number

  variant low when stock < 10
  variant normal when stock >= 10
}

Tek input, entity field adı ve tipiyle eşleşirse generated table, detail ve form preview alanlarında otomatik kullanılabilir.

theme

`.blackthm`, BlackLang'in UI tema ve profil bilgisini raw CSS yerine deterministik kaynak olarak saklaması için eklenen ilk dosya formatıdır. Generator artık bu dosyadaki okuma sırasını kullanarak kompakt inline UI değerlerini CSS property'lerine bağlayabilir.

Warehouse theme profile
blackthm WarehouseTheme {
  version 1
  target web
  locked true

  token color primary "#2563eb"
  token color surface "#ffffff"
  token space sm 8
  token radius md 6

  profile UICompact {
    version 1
    baseline box color width style pt pr pb pl radius place
    baseline text color size weight align
    baseline table color width style density zebra
    baseline button bg color radius size variant

    ui box = color width style pt pr pb pl radius place;
    ui text = color size weight align;
    ui table = color width style density zebra;
    ui button = bg color radius size variant;
  }
}
Inspect command
black theme inspect --json
black theme inspect examples/warehouse/theme.blackthm --ir

Hex renkler tırnak içinde yazılır, çünkü `#` tırnak dışında comment başlatır. `profile.modeGroups` standart UI gruplarını, `profile.baselines` kilitli sırayı, `profile.modes[].slots` ise güncel sırayı gösterir. Compiler, locked profilde UI slot sırasının baseline ile başlamasını zorunlu tutar.

ui-profile

UI profile, `.black` içinde yazılan kompakt `ui` satırlarının hangi sırayla okunacağını belirler. Amaç, CSS benzeri uzun anahtarlar yazmadan generator için tek anlamlı bir stil niyeti vermektir.

Slot order
profile UICompact {
  version 1
  baseline box color width style pt pr pb pl radius place
  baseline text color size weight align
  baseline table color width style density zebra
  baseline button bg color radius size variant

  ui box = color width style pt pr pb pl radius place;
  ui text = color size weight align;
  ui table = color width style density zebra;
  ui button = bg color radius size variant;
}
Inline mapping
ui box black 1 solid 8 8 5 5 6 center | text "#172026" 14 regular left

Değerler soldan sağa okunur. Eksik sondaki değerler default alır, fazladan değer hata sayılır, aynı mode içinde aynı slot iki kez yazılamaz. Profile kilitlendiğinde mevcut slotlar taşınamaz; yeni slotlar sadece sona eklenir. `ui = ;` generator'ın okuma sırasıdır. Araya slot eklenirse compiler `NON_APPEND_ONLY_UI_SLOT` hatası verir.

ui-modes

Standart UI mode grupları, kompakt `ui` satırlarının hangi görsel bağlama ait olduğunu compiler ve AI ajanı için açık hale getirir. Web profilleri `box`, `text`, `table` ve `button` gruplarını içermelidir.

Standart gruplar
box     form, panel ve component container stilleri
text    label, heading, help text ve body typography
table   tablo border, density ve row pattern stilleri
button  generated veya explicit action control stilleri
Theme inspect JSON
{
  "profile": {
    "modeGroups": [
      {
        "name": "box",
        "required": true,
        "defaultSlots": ["color", "width", "style", "pt", "pr", "pb", "pl", "radius", "place"],
        "appliesTo": ["field", "form", "table", "component", "panel"]
      }
    ],
    "modes": [
      {
        "name": "box",
        "standard": true,
        "slots": ["color", "width", "style", "pt", "pr", "pb", "pl", "radius", "place"]
      }
    ]
  }
}

Standart gruplardan biri eksikse `black theme inspect --json` `MISSING_STANDARD_UI_MODE` diagnostic kodu döner. Bu kural, inline UI intent ve CSS generation aşamalarında her projenin aynı temel görsel sözlüğü paylaşmasını sağlar.

inline-ui

`ui`, görsel niyeti `.black` dosyasında ilgili field, form, table veya action button yanında tutar. Web target artık bu intent bilgisinden stable `.bl-ui-*` class adları ve `src/styles.css` içinde CSS kuralları üretir.

Field, table, form ve action button
entity Product {
  name text required ui text "#172026" 14 semibold left
}

page Products {
  source Product

  table {
    id ProductsTable
    class inventoryTable
    columns name
    ui table border 1 solid compact true
  }

  form {
    id ProductForm
    class inventoryForm
    fields name
    ui box black 1 solid 8 8 5 5 6 center | text "#172026" 14 regular left
  }

  actions create
  action create id CreateProductButton
  action create class primaryAction
  action create ui button primary white 6 md solid
}
Explicit UI identity
table {
  id ProductsTable
  class inventoryTable compactPanel
}

form {
  id ProductForm
  class inventoryForm
}

action create id CreateProductButton
action create class primaryAction
Geçerli mode bağlamları
field   box, text
form    box, text, button
table   box, text, table
button  button

`action create ui button ...`, aynı page içindeki `actions create` listesine bağlıdır. Mode hataları `UNSUPPORTED_UI_MODE`, yanlış bağlamlar `UNSUPPORTED_UI_TARGET_MODE`, tekrar eden mode kullanımı `DUPLICATE_UI_INTENT` olarak raporlanır. `id` ve `class` değerleri generated HTML'de kebab-case'e çevrilir; row action butonlarında tekrarlı DOM id oluşmaması için `-item-<recordId>` gibi suffix'ler eklenir. Field satırında normal modifier'lar `ui` öncesinde kalmalıdır.

Generated class düzeni
table   .bl-ui-table-<page>
form    .bl-ui-form-<page>
field   .bl-ui-field-<entity>-<field>
action  .bl-ui-action-<page>-<action>

i18n

`i18n`, generated web uygulamasında kullanılacak varsayılan dili ve desteklenen locale listesini tanımlar. İlk çalışan kapsam field label çevirileridir.

Locale ve field label translation
i18n {
  default tr
  locales tr, en
}

label Product.name {
  tr "Ürün Adı"
  en "Product Name"
}

Generator default locale çevirisini form label, table header, detail label, column visibility label, filter label ve frontend validation label alanlarında kullanır. Çeviri yoksa önce field üzerindeki `label "Text"`, sonra field adının title-case hali kullanılır.

Generated label fallback sırası
1. label Product.name { tr "Ürün Adı" }
2. name text label "Product Name"
3. name -> Name

Runtime dil değiştirme, translation key sistemi, placeholder/help/message çevirileri, date/number/currency formatları ve RTL desteği sonraki genişleme alanlarıdır.

api

`api`, generated CRUD dışındaki contract-first endpoint niyetlerini anlatır. Runtime implementation daha sonra gelişebilir; v0.1 bu bilgiyi OpenAPI çıktısına taşır.

Explicit API contract
api LowStockReport {
  method GET
  path "/api/reports/low-stock/{warehouseId}"
  param warehouseId text
  query limit integer
  private
}

api StockWebhook {
  method POST
  path "/api/webhooks/stock"
  webhook
  public
}

`black build` generated OpenAPI contract oluşturur. Generated Express server bu contract'ı `/openapi.json` üzerinden servis edebilir.

security

BlackLang kaynak dosyaları yüksek değerli source asset olarak görülür. Secret, password, API key, token ve private key değerleri `.black` dosyasına yazılmamalıdır.

Doğru secret yaklaşımı
database {
  url env DATABASE_URL
}

security {
  cors {
    origins env CORS_ORIGINS
    credentials true
  }
}
Kaçınılacak kullanım
database {
  url "postgres://user:password@example.com/app"
}

Production deployment için hedef, mümkünse `.black` kaynaklarını sunucuya taşımadan generated production artifact yayınlamaktır. `black security scan --json` olası hardcoded secret izlerini raporlar.

cors

`cors`, tarayıcıdan generated API'ye hangi origin'lerin erişebileceğini tanımlar. Domain listesi `.black` içine gömülmez; deployment ortamında environment olarak verilir.

CORS policy
security {
  cors {
    origins env CORS_ORIGINS
    credentials true
  }
}

Generated Express server `CORS_ORIGINS` değerini virgülle ayrılmış liste olarak okur, listede olmayan browser origin'lerini `403` ile reddeder, `OPTIONS` preflight yanıtı üretir ve `credentials true` varsa cookie-auth uyumlu header ekler.

deploy

`deploy`, generated web uygulamasının production ortamında nasıl ayağa kalkacağını tarif eder. İlk çalışan hedef Docker'dır.

Docker deployment
deploy {
  target docker
  port env PORT default 3001
  env DATABASE_URL required
  env CORS_ORIGINS optional
}

Bu niyet `Dockerfile`, `.dockerignore`, `docker-compose.yml`, `.env.example` içinde `PORT`, generated `package.json` içinde `start` scripti ve generated server içinde `process.env["PORT"]` kullanımı üretir. Mevcut runtime SQLite tabanlı olduğu için PostgreSQL target'ı sonraki runtime aşamasına bırakılmıştır.

Hata Çıktıları

Hatalar stabil code, dosya, satır, kolon ve öneri alanlarıyla dönmelidir. Böylece AI ajanı hata metnini yorumlamak yerine error code üzerinden doğru referansa gider.

JSON error shape
{
  "success": false,
  "errors": [
    {
      "file": "examples/warehouse/app.black",
      "line": 17,
      "column": 13,
      "code": "UNKNOWN_TABLE_COLUMN",
      "message": "Page Products table uses unknown field Product.barcode.",
      "suggestion": "Add the field to the source entity or remove it from columns."
    }
  ]
}

Bu model, insan için okunabilir; AI için de deterministik onarım akışı sağlar. AI ajanı hata metnine göre değil, `code` alanına göre karar vermelidir. Tam referans `/diagnostics.md` ve `docs/diagnostics.md` içinde tutulur; kısa CLI açıklaması `black docs diagnostics --json` ile alınabilir.

Diagnostic code families
UNKNOWN_*     referenced symbol does not exist
DUPLICATE_*   declaration appears more than once
MISSING_*     required block, field, value, or option is absent
INVALID_*     syntax or value shape is malformed
UNSUPPORTED_* value is known but not supported in this version
UNCLOSED_*    block or string is not closed
UNEXPECTED_*  token is not valid in that location
HARDCODED_*   likely secret is stored in source

Bu bölüm dış AI ajanlarının BlackLang'i yanlış yorumlamasını engeller. Resmi çalışma yolu `.black` kaynak, `.blackthm` tema profili ve `black` CLI üzerinden generated web output üretmektir.

Resmi akış
black agent startup --json
black docs agent-contract --json
black inspect app.black --json

black lint --json
black validate --json
black build

Şu an BlackLang genel amaçlı browser runtime değildir. Calculator, game, custom click handler veya arbitrary JavaScript replacement gibi davranışlar ilerideki frontend logic/event aşamalarına aittir. Entity tabanlı computed display değerleri desteklenir; calculator tarzı lokal expression state henüz desteklenmez.

Desteklenmeyen resmi syntax
<script type="text/black">
  button 7
</script>

Bir AI ajanı desteklenmeyen bir işi normal HTML/JavaScript ile prototiplerse bunu açıkça prototip olarak etiketlemelidir. Resmi BlackLang çıktısı demek, desteklenen `.black` syntax'ının resmi `black` compiler tarafından üretilmesi demektir.
