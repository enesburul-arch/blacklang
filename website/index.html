BlackLang Documentation

BlackLang

BlackLang, AI ajanlarının uygulama niyetini kısa, net ve doğrulanabilir bir kaynak dille yazması için tasarlanan deterministik bir dildir.

Current version: 0.1.0-dev Target: Web + API-only applications Source: .black / .black.enc Theme: .blackthm
Minimal fikir
Human request
  to AI coding agent
  to .black source
  to black compiler
  to generated web/API application

İlk hedef Python veya JavaScript'i tamamen değiştirmek değildir. İlk hedef, web uygulamalarında tekrar eden model, form, tablo, validation, API ve güvenlik niyetlerini daha küçük bir kaynak temsille anlatmaktır.

Quick Start

En küçük çalışan akış bir `.black` dosyası yazmak, validate etmek ve web çıktısı üretmektir. AI ajanı da insan geliştirici de aynı dosyayı okuyup aynı sonucu alır.

examples/warehouse/app.black
app Warehouse

entity Product {
  sku text required unique
  name text required
  photo image optional accept "image/*"
  stock number default 0
  price money
  computed inventoryValue money = stock * price label "Inventory Value"
}

action RestockProduct {
  source Product
  input quantity number required min 1 label "Quantity"
  value restockValue = quantity
  if restockValue > 0 and stock >= 0
    set stock = stock + restockValue
  else
    set stock = stock
  success "Stock updated"
}

transaction RestockAtomic {
  action RestockProduct
}


page Products {
  source Product

  table {
    columns sku, name, stock, price, inventoryValue
    search sku, name
  }

  form {
    fields sku, name, stock, price
  }

  actions create, edit, delete, RestockProduct
}

Bu blok Product verisini, Products ekranını, tablo kolonlarını, form alanlarını ve CRUD/custom action davranışlarını tek kaynakta toplar. Generator bu niyetten TypeScript, React, API, validation ve database tarafını üretir.

Kurulum

BlackLang'in hedef dağıtımı tek binary modelidir. Olgun sürümde kullanıcı sadece `black` komutunu indirip çalıştırabilmelidir; compiler için ayrıca Python veya Node.js zorunlu olmamalıdır.

Bugünkü public bootstrap
git clone https://github.com/enesburul-arch/blacklang.git
cd blacklang/packages/cli
go run ./cmd/black --help
go run ./cmd/black version --json
go run ./cmd/black docs agent-contract --json
go run ./cmd/black validate ../../examples/warehouse/app.black --json
go run ./cmd/black build ../../examples/warehouse/app.black --out ../../generated --json

`black` komutu sistemde yoksa resmi geçici yol budur: repo klonlanır ve CLI `packages/cli` içinden `go run ./cmd/black ...` ile çalıştırılır. Signed GitHub Release arşivleri ve npm yolu yaygın public kurulum için planlanır; npm paketi platforma uygun binary'yi çağırır, compiler mantığı yine tek binary içinde kalır.

Syntax Temeli

Dil kısa olmalı ama şifreli olmamalıdır. `app`, `target`, `entity`, `page`, `table`, `form`, `actions`, `when` gibi tanıdık kelimeler AI'nin ilk okuma maliyetini düşürür.

Top-level bloklar
app Warehouse

target web {
  frontend react
  backend node
  database sqlite
}

entity Product {
  name text required
}

page Products {
  source Product
}

Her davranış için tek syntax hedeflenir. Bu, hem compiler hatalarını daha stabil yapar hem de AI ajanının "hangi kullanım doğru" diye tahmin yürütmesini azaltır.

app

`app`, uygulamanın adını belirler. Bir BlackLang projesinde tam olarak bir ana uygulama adı olmalıdır.

Syntax
app Warehouse

Generator bu adı package metadata, arayüz başlığı ve çıktı dokümantasyonu gibi yerlerde kullanabilir. İsim PascalCase yazıldığında hem insan hem AI için daha okunaklı kalır.

target

`target`, `.black` kaynağının hangi platform ve generated stack için yazıldığını açıkça belirtir. Current web generator React frontend, Node backend ve SQLite, PostgreSQL veya MySQL runtime üretebilir; API-only target aynı backend/runtime yüzeyini React ve Vite dosyaları olmadan üretir.

Web target
target web {
  frontend react
  backend node
  database sqlite
}
API-only target
target api {
  backend node
  database sqlite
}

PostgreSQL için aynı blokta `database postgres`, MySQL için `database mysql` yazılır. Bu seçim Prisma provider'ı, provider adapter'ı ve Docker Compose database servisi üretir. `target api`, Express server, Prisma, OpenAPI, validation, API smoke test, seed/job/deploy/ops çıktısını üretir; `index.html`, Vite, React page/component, frontend smoke, browser-check, browser e2e ve matrix dosyalarını üretmez. Browser `test` deklarasyonları yalnızca `target web` içinde desteklenir. Mobile, desktop veya farklı backend hedefleri generator gerçekten o çıktıları üretebildiğinde açılmalıdır. Blok yoksa mevcut generator eski varsayılan stack'i kullanır: `web`, `react`, `node`, `sqlite`.

entity

`entity`, saklanacak uygulama verisini anlatır. Normal web stack'te model, validation, database schema ve API type parçalarına bölünen niyet burada tek blokta ifade edilir.

Ürün modeli
entity Product {
  sku text required unique length 3..40
  name text required label "Product Name"
  photo image optional accept "image/*" label "Product Photo"
  stock number default 0 min 0
  price money min 0
  computed inventoryValue money = stock * price label "Inventory Value"
  index stock
}

Field adı solda, tipi yanında, kuralları ise aynı satırda yer alır. `image` yerel formdan data URL olarak okunan stored media field üretir. `computed` database kolonu değildir; `index` ise stored field database index niyetini generator'a taşır. Bu sıra, AI'nin satırı tek seferde okuyup veri niyetini anlamasını kolaylaştırır.

computed

`computed`, saklanan field'lardan okuma amaçlı hesaplanan değer üretir. İlk sürümde database kolonu değildir, form input'u değildir; generated table ve detail UI içinde hesaplanır.

Computed display field
entity Product {
  stock number default 0
  price money default 0
  tax money default 0
  computed inventoryValue money = stock * (price + tax) label "Inventory Value"
}

page Products {
  source Product

  table {
    columns stock, price, inventoryValue
  }
}

v0.2 syntax'ı `computed name type = numericExpression` şeklindedir. Desteklenen tipler `number`, `integer`, `decimal`, `money`; expression içinde `+`, `-`, `*`, `/`, parantez ve deterministic operator precedence desteklenir. Operand'lar aynı entity içindeki number-like field'lar veya numeric literal değerler olmalıdır.

Generated React mantığı
function computeInventoryValue(item: Product) {
  const value = Number(item.stock ?? 0) * Number(item.price ?? 0);
  return Number.isFinite(value) ? value : null;
}

Bir computed field, kaynak aldığı field'lardan biri role/field-level permission ile gizlenmişse generated UI'da kendisi de gizlenir. Search, filter ve sort desteği sonraki data logic aşamasına bırakılmıştır.

media

`file` ve `image`, generated web app içinde yerel dosya seçimi için stored scalar field tipleridir. Generator upload provider kurmaz; form seçilen dosyayı data URL olarak okur, API validation zincirinden geçirir ve string kolon olarak saklar.

Local media fields
entity Product {
  photo image optional accept "image/*" label "Product Photo"
  specSheet file optional accept "application/pdf" label "Spec Sheet"
}

page Products {
  source Product

  table {
    columns photo, specSheet
  }

  form {
    fields photo, specSheet
  }
}

Generated UI image değerlerini thumbnail, file değerlerini link olarak gösterir. OpenAPI içinde `x-blacklang-media` ve `x-blacklang-encoding: data-url` metadata'sı yer alır. `accept` sadece file/image entity field'larında geçerlidir; storage bucket, token ve özel endpoint değerleri `.black` içine yazılmaz.

AI commands

black explain media --json
black inspect examples/warehouse/app.black --affected Product.photo --json

relation-load

Relation load policy, entity relation field'larının generated API response içinde hangi context'lerde ilişki objesini attach edeceğini `.black` kaynakta belirler. Böylece tablo, detay, query sonucu ve mutation response davranışı generated JS'e dokunmadan, deterministic ve AI-readable kalır.

Relation response load policy
entity Order {
  customer Customer required load list detail query mutation label "Customer"
  total money default 0
}

Desteklenen scope'lar `list`, `detail`, `query`, `mutation` ve `none` değerleridir. `load` yazılmazsa eski davranış korunur ve relation obje tüm response context'lerinde attach edilir. `load none`, sadece generated relation ID field'ını bırakır. Generated list/query route'lar relation ID'lerini batch toplayıp her relation field için tek target lookup yapar; permission-aware build attached target record'ları sanitize eder. Bu policy database schema'yı değiştirmez ve custom query filtrelerine relation join eklemez.

AI commands
black docs relation-load --json
black explain relation-load --json
black inspect examples/warehouse/app.black --affected Order.customer --json

Generated OpenAPI operations `x-blacklang-relation-load-context` ve `x-blacklang-relation-load` metadata'sı taşır. Bu metadata, ajanların hangi route response'unun relation object beklediğini hızlıca anlamasını sağlar.

index

`index`, stored entity field'ları için database index niyetini `.black` kaynakta tutar. Generator Prisma schema içinde `@@index`, SQLite setup içinde de `CREATE INDEX IF NOT EXISTS` üretir.

Stored field index
entity Order {
  customer Customer required
  status text default draft
  index customer, status
}

Relation field index'leri generated foreign-key kolona maplenir; örneğin `index customer, status`, Prisma tarafında `@@index([customerId, status])` olur. Computed display field'lar database kolonu olmadığı için indexlenemez. Index değişikliği için `black inspect app.black --affected Order.index --json` generated database schema/setup etkisini gösterir.

migration

`migrate plan`, eski ve yeni `.black` source dosyasını karşılaştırır ve generated database shape değişikliklerini deployment öncesi risk seviyelerine ayırır. Komut read-only çalışır; database'e bağlanmaz, SQL uygulamaz, dosya yazmaz. Explicit rename deklarasyonları ise generated `db:setup`/`db:push` içinde schema setup öncesi idempotent uygulanır.

Read-only schema migration plan
black migrate plan app-v1.black app-v2.black --json
black migrate plan app-v1.black app-v2.black --ir

JSON çıktısında `success`, `safe`, `destructive`, `summary`, `changes`, `steps` ve `changes[].risk` alanları bulunur. `safe` risk stored data shape'i koruyan değişiklikleri ve explicit rename'i, `manual` backfill veya veri kontrolü isteyen değişiklikleri, `destructive` ise tablo/kolon silme, generated kolon adı değişimi veya tip dönüşümü gibi veri kaybı ihtimali olan değişiklikleri ifade eder.

Explicit rename migration
migration RenameProductName {
  rename entity ProductItem to Product
  rename field Product.title to name
}

Entity ve field rename otomatik tahmin edilmez. `to` entity veya stored field current source içinde var olmalı, `from` adı current source içinde kalmamalıdır. Build çıktısı `migrations/manifest.json`, `migrations/*.sql`, `src/migrate.ts`, `src/setup-db.ts` ve Prisma `BlackMigration` ledger modelini üretir.

Generated migration runner
npm run db:migrate:plan
npm run db:migrate
npm run db:setup

`db:migrate:plan` target database'e read-only bakar; SQLite'ta eksik DB dosyasını oluşturmaz ve PostgreSQL connection string değerini JSON'a basmaz. `db:migrate` yalnızca declared rename migration'larını uygular, sonucu `BlackMigration` ledger'ına işler ve ardından `db:setup` normal generated setup ve seed yolunu çalıştırır.

Seed değerleri stored field'lara yazılır. Text/email/date/datetime literal'ları tırnaklıdır; numeric ve boolean değerler tırnaksızdır. Relation field'lar `ref OtherRowKey` kullanır ve referans verilen row ilgili entity için tanımlı olmalıdır. Computed display field, generated system field, raw SQL, expression, environment read ve secret değerleri seed içinde desteklenmez.

query

`query`, düşük stok gibi özel listeleri saklanan entity field'ları üzerinden tanımlar. Filtre, aggregate summary, sıralama ve kayıt sınırı server tarafında uygulanır; aynı sorgu birden fazla generated sayfaya bağlanabilir.

Warehouse: düşük stok listesi
query LowStockProducts {
  source Product
  where stock < 10
  aggregate lowStockCount count
  aggregate totalStock sum stock
  aggregate averagePrice avg price
  sort stock asc
  limit 50
}

page LowStock {
  source Product
  query LowStockProducts

  table {
    columns sku, name, stock, price, inventoryValue
    search sku, name
    paginate 10
  }

  actions RestockProduct
}

Bu örnek, yukarıdaki Product modelinden stok adedi 10'dan küçük olan en fazla 50 ürünü seçer. Stok artan sıradadır; eşit stok değerlerinde `id asc` kullanılır. LowStock sayfası `RestockProduct` aksiyonunu kullanır; aksiyon sonrası query ve summary tekrar yüklenir. Summary kartları düşük stok sayısını, toplam stoğu ve ortalama fiyatı gösterir. Computed `inventoryValue` tabloda gösterilebilir; query koşulunda, sort alanında veya aggregate field olarak kullanılamaz.

Query top-level tanımlanır ve tek `source Entity` kullanır. Sayfa kendi `source` satırını korur, `query Name` ile sorguya bağlanır; iki source aynı olmalıdır. Birden fazla `where` satırı AND ile birleşir. `aggregate name count` rows sayar; `aggregate name sum|avg|min|max field` stored numeric field ister. Tek bir opsiyonel `sort field asc|desc` kullanılabilir. Sort yoksa varsayılan `id asc`; limit yoksa varsayılan 100'dür. `limit`, 1 ile 1000 arasında tam sayı olmalıdır.

Field tipine göre literal örnekleri
where status == "draft"
where stock < 10
where price >= 12.50
where active == true
where dueDate < "2026-09-06"
where scheduledAt >= "2026-09-06T12:00:00Z"

Her koşul query source entity'sinde bulunan, örnekteki tipe uygun bir field gerektirir. Text/email/date/datetime değerleri tırnaklı, numeric ve boolean değerler tırnaksızdır. `number` ve `integer` 32-bit tam sayı; `decimal` ve `money` sonlu ondalık literal kabul eder. `==` ve `!=` tüm desteklenen stored primitive tiplerde; `<`, `<=`, `>`, `>=` numeric/date/datetime tiplerinde geçerlidir. Relation, computed ve generated system field'ları, parametreler, OR, join, raw SQL ve arbitrary code bu MVP'nin dışındadır.

Generated LowStock sayfası `GET /api/lowstock/query` ve `GET /api/lowstock/query/summary` üzerinden yüklenir. Summary route aynı source, where, archive ve row policy kurallarını kullanır; sort ve limit'i uygulamaz. Mevcut entity listesi ve CRUD route'ları kendi davranışını sürdürür; relation seçenekleri normal entity listesinden gelir. Sayfaya bağlanmamış query bağımsız endpoint oluşturmaz. Table search/filter/pagination ve opsiyonel table sort, server'ın döndürdüğü sınırlı liste üzerinde çalışır. Bağlı sayfadaki başarılı mutation sonrası query yeniden yüklenir.

Auth, page access, entity read, response field hiding ve entity row policy kuralları korunur. Koşul, sort veya aggregate alanı mevcut role için okunabilir değilse query endpoint'i 403 döndürür. Query filtreleri liste seçimidir; ownership/tenant authorization için entity içinde `policy` kullanılır.

black validate --json
black build --json

job

`job`, public endpoint açmadan generated worker içinde read-only query işi çalıştırır. İlk MVP güvenli ve deterministik kalır: tek schedule syntax'ı, tek run mode ve query tabanlı kayıt seçimi vardır.

Warehouse: düşük stok monitor job'u

  schedule every 15 minutes
  run query LowStockProducts

action

`action`, CRUD dışındaki güvenli satır işlemlerini `.black` içinde tanımlar. Örneğin stok eklemek, bir talebi onaylamak veya bir kaydı iş kuralına göre güncellemek için tek bir deterministik action declaration kullanılabilir.

Warehouse: stok ekleme aksiyonu
action RestockProduct {
  source Product
  input quantity number required min 1 label "Quantity"
  value restockValue = quantity
  if restockValue > 0 and stock >= 0
    set stock = stock + restockValue
  else
    set stock = stock
  allow Admin, Worker
  success "Stock updated"
}

transaction RestockAtomic {
  action RestockProduct
  api StockWebhook
}

page Products {
  source Product
  actions edit, RestockProduct
}

Action top-level tanımlanır ve tek `source Entity` kullanır. Page aynı source ile `actions ..., ActionName` yazdığında generator route, client metodu, input validation, row button, form panel, OpenAPI schema ve auth/role varsa audit log üretir. Page'e bağlanmamış action bağımsız endpoint oluşturmaz.

Input'lar primitive field type ve normal validation modifier kullanır. `number` ve `integer` mevcut SQLite/Prisma runtime'da 32-bit tam sayı olarak validate edilir; kesirli değer için `decimal` veya `money` kullanılmalıdır. Input adı source entity field adıyla çakışamaz; böylece `set` expression içindeki identifier'ların anlamı tek kalır.

`value`, action içinde sıralı local expression adı üretir; daha sonraki `value`, `set` ve `if` satırları bu adı kullanabilir. Python-like indentation-based `if`/`else` branch'leri `value`, `set` ve nested `if` statement'larını taşır. `set`, yalnızca saklanan primitive source field'larını değiştirebilir. Değerler typed literal, action input, source field, local value veya bounded numeric expression olabilir. Numeric expression için `+`, `-`, `*`, `/`, parantez ve deterministic precedence desteklenir. Condition comparison'ları `==`, `!=`, `<`, `<=`, `>` ve `>=` kullanır; comparison'lar `and`, `or`, `not` ve parantez ile bağlanabilir, precedence `not`, sonra `and`, sonra `or` şeklindedir. Computed display field, relation field, entity policy field, join, aggregate, raw SQL, function call, loop, external call ve multi-row mutation MVP dışındadır.

Atomic çalışma niyeti action içinde değil, top-level `transaction` bloğunda durur. Böylece action yalnızca mutation'ı anlatır; transaction bloğu generated action/API update route'unun source row lookup, deterministic update ve auth/role varsa audit log yazımını tek `prisma.$transaction` içinde çalıştırır.

Generated runtime contract
POST /api/products/:id/actions/restockproduct

{
  "quantity": 7
}

Runtime page access, entity update permission, yazılan her field için field-level update permission, entity row policy ve opsiyonel action `allow` kuralını birlikte uygular. Query-bound sayfada aksiyon başarılı olursa liste server query'den tekrar yüklenir.

transaction

`transaction`, mevcut custom action veya explicit API update handler için atomic generated runtime boundary bildirir. Yeni endpoint üretmez; hangi write route'unun Prisma transaction içinde çalışacağını deterministik şekilde işaretler.

Action/API update route transaction binding
transaction RestockAtomic {
  action RestockProduct
  api StockWebhook
}

Her hedef tek satırdır: `action ActionName` veya `api ApiName`. API hedefleri bounded single-line veya block-form update handler'a sahip olmalıdır. Bir action/API aynı anda yalnızca bir transaction bloğuna bağlanabilir.

Generator targeted custom action route'larında ve explicit API update handler'larında lookup, update ve audit log işini `prisma.$transaction` içine alır. Request parsing, auth, page access ve field permission kontrolleri transaction açılmadan önce çalışır. OpenAPI targeted operasyonlara `x-blacklang-transaction` ve `x-blacklang-transaction-name` metadata'sı ekler.

AI için kısa öğrenme ve etki analizi
black docs transaction --json
black explain transaction --json
black inspect --affected RestockAtomic --json
black validate --json
black build --json

service

`service`, mevcut explicit API deklarasyonlarını generated service/module metadata altında gruplar. Endpoint üretmez ve handler tanımlamaz; route sözleşmesi hâlâ top-level `api` bloğundadır. Service bloğu AI ajanları, OpenAPI client üreticileri ve API-only projeler için hangi endpointlerin aynı servis yüzeyine ait olduğunu kompakt biçimde görünür kılar.

Explicit API service grouping
service InventoryIntegration {
  api StockWebhook
}

`api`, generated CRUD dışındaki explicit endpoint niyetlerini anlatır. v0.2 bu bilgiyi OpenAPI çıktısına taşır ve generated Express server içinde declared-runtime route olarak üretir. POST/PUT/PATCH endpointleri typed body doğrulaması ve bounded update handler ile güvenli iş mantığı taşıyabilir.

Explicit API declared runtime
api LowStockReport {
  method GET
  path "/api/reports/low-stock/{warehouseId}"
  param warehouseId text

api StockWebhook {
  method POST
  path "/api/webhooks/stock"
  body tenantId text required
  body sku text required
  body stock number required min 0
  update Product where sku == body.sku {
    value incomingStock = body.stock
    if incomingStock >= 0 and tenantId == body.tenantId
      set stock = incomingStock
    else
      set stock = stock
  }
  respond accepted
  webhook
  public
}

protected source

`.black.enc`, BlackLang kaynak dosyasını production paketlerinden ayırmak ve gerektiğinde güvenilir developer/CI ortamında bellekten build etmek için eklenen protected source formatıdır.

ops

`ops`, generated web uygulamasına public runtime probe endpoint'leri ve structured request log niyeti ekler. Bu bölüm deploy sonrası “process ayakta mı, database hazır mı, temel sayaçlar ne durumda?” sorularını generated dosya düzenlemeden cevaplar.

Runtime operation signals
ops {
  health path "/healthz"
  readiness path "/readyz"
  metrics path "/metrics"
  logging requests
  observe otlp endpoint env BLACKLANG_OTLP_ENDPOINT
}

`health path`, uptime, start time, app adı ve compiler version bilgisini dönen public GET endpoint üretir. `readiness path`, generated database adapter üzerinden `SELECT 1` çalıştırır ve database ulaşılamazsa `503` döner. `metrics path`, process-local request, error ve status-code sayaçlarını gösterir. `logging requests`, her gözlenen istek bitince tek satır JSON log yazar. `observe webhook endpoint env NAME`, env set edilmişse response yolunu bloklamadan structured request event POST eder. `observe otlp endpoint env NAME` aynı observe syntax'ı ile non-blocking OTLP HTTP JSON trace payload üretir. Observe middleware W3C `traceparent` context üretir veya gelen context'i taşır.

Ops path'leri root-level public path olmalıdır; `/api`, `/openapi.json`, query string, fragment, brace, whitespace ve unsafe karakterler reddedilir. Route'lar API auth ve CSRF middleware'inden önce üretildiği için infrastructure health check'leri login akışına takılmaz.
