# BlackLang Diagnostics

This document is the stable reference for BlackLang diagnostic codes.

Diagnostics are emitted by parser, validator, formatter, linter, generator, security, packaging, docs, IDE tooling, and AI inspection commands.

## Contract

Every diagnostic must keep this JSON shape:

```json
{
  "file": "examples/warehouse/app.black",
  "line": 17,
  "column": 13,
  "code": "UNKNOWN_TABLE_COLUMN",
  "message": "Page Products table uses unknown field Product.barcode.",
  "suggestion": "Add the field to the source entity or remove it from columns."
}
```

Rules:

- `code` is the stable machine-readable key.
- `message` explains what happened for humans.
- `suggestion` tells the next repair step when possible.
- `file`, `line`, and `column` should point at the source of the problem when available.
- Do not reuse an old code for a different meaning.
- If a code is renamed, document the migration in the same change.
- AI agents should branch on `code`, not on `message` text.

## Agent Repair Order

Use this order when multiple diagnostics exist:

1. Fix file, init, package, and build path errors.
2. Fix lexer and parser errors such as `UNCLOSED_*`, `UNEXPECTED_*`, and `INVALID_*_DECLARATION`.
3. Fix semantic missing/duplicate/unknown references.
4. Fix unsupported feature usage.
5. Fix source-security findings before packaging or deployment.

## Code Families

```text
FILE_*       filesystem read/write problems
INIT_*       project scaffold problems
FORMAT_*     deterministic formatting problems
BUILD_*      generator output problems
BENCHMARK_*  source/generated measurement problems
PACKAGE_*    production package problems
HARDCODED_*  likely source secret findings
ENCRYPTION_* protected source encryption problems
INVALID_*    malformed syntax or malformed value
MISSING_*    required declaration or value is absent
DUPLICATE_*  same declaration appears more than once
UNKNOWN_*    reference points to a symbol that does not exist
UNSUPPORTED_* value is known but not supported in this version
UNCLOSED_*   block or string was not closed
UNEXPECTED_* token is valid text but invalid in that location
AUTH_*       auth prerequisite diagnostics
ACCESSIBILITY_* generated UI accessibility policy diagnostics
INCOMPATIBLE_* semantic type mismatch diagnostics
UNUSED_*     declaration exists but is not used by its target
```

`black migrate plan <old.black> <new.black> --json` returns `MISSING_SCHEMA_MIGRATION_FILES` when one of the two required source files is missing from the command. First-class rename syntax uses `migration Name { rename entity Old to New; rename field Entity.old to new }`. Parser and validator diagnostics reject malformed declarations, duplicate migration names/renames, unknown current rename targets, computed-field targets, and old source names that still remain in the current source. Valid migration risks are reported in `changes[].risk`; they are not diagnostics.

`black audit accessibility --json` returns `ACCESSIBILITY_MISSING_OVERLAY_TITLE` when a generated modal/drawer section lacks an explicit `title`, and `ACCESSIBILITY_MISSING_GROUP_TITLE` when a multi-section view group lacks an explicit `title`.

## Common Fix Patterns

```text
UNKNOWN_*     add the referenced symbol or remove the reference
DUPLICATE_*   keep one declaration and delete or rename the duplicate
MISSING_*     add the required block, field, value, or option
INVALID_*     rewrite the syntax to match the documented shape
UNSUPPORTED_* use a supported current-version value or wait for a later language phase
UNCLOSED_*    add the missing closing quote or brace
UNEXPECTED_*  move the token to a valid block or remove it
HARDCODED_*   move secret values to env or a secret manager
ENCRYPTION_*  check the key environment variable, output path, and encrypted-source runtime
DECRYPTION_FAILED check the key value and encrypted file header
```
